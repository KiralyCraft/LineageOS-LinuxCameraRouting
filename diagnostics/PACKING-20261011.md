# Packing and synchronization investigation

Candidate: 0.1.4, source additions on top of 0772aeb. No kernel/protocol changes.
The installed 0.1.3 Magisk module and broker remain compatible.

## Implemented measurement boundary

The native producer records eight independent wall-time stages, in fixed-size
in-memory histograms: image acquisition, destination mapping, source access,
DMA-BUF sync start, packing, sync end, completion, and image release. Summaries
are emitted on stream retirement. Each stream resets its metrics. p95 values
are histogram upper bounds, not exact percentiles. Destination mapping includes
cheap existing-map lookups; initial exports/maps contribute to its first frames.
Source plane access can include HAL locking/cache handling, and acquisition may
wait for source readiness. Thus time outside the explicit DMA-BUF sync ioctls
must not automatically be called pure memory copying.

The reference implementation and candidate can be selected between streams
through the existing non-exported Android service. Candidate remains opt-in
pending Camera2/V4L2 measurements and image checks. Startup uses reference mode.

## Candidate

Shared bounds validation before writing any pixel. Contiguous planar data uses
one memcpy where possible. For adjacent U/V views with matching stride and
pixel stride 2, one AArch64 `vld2q_u8` loop deinterleaves complete 16-pair blocks
and stores the two output planes; a scalar tail touches no padding bytes.
NV12 and NV21 component order is preserved. Unsupported layouts retain a
fully stride-aware generic path. No arithmetic on color sample values, scaling,
extra buffer, frame queue or new dependency is introduced.

## Tests passed

- Existing packing ASan/UBSan test on build server.
- 224 additional guard-page cases, under ASan/UBSan on the build server and
  natively on the phone: NV12, NV21, planar and generic stride; cropped/padded
  planes; widths around the vector boundary; unaligned addresses and short
  final rows; independent coordinate expectations; exact reference agreement;
  no destination writes after invalid-plane rejection.
- Timing histogram sample count, upper-bound and maximum checks.
- Native APK builds with strict C99 warnings; disassembly contains AArch64 LD2.

## Phone ordinary-memory benchmark

Four source/destination slots; alternating reference/fast order each iteration;
four warmup iterations and 64 measured operations per implementation per size.
No CPU affinity or frequency changes. Native Android binaries built on the
requested server. Output is timing text only in Android tmpfs / Linux RAM-backed
/tmp. This benchmark does not use camera gralloc buffers or destination DMA-BUF
cache synchronization and cannot establish live capture speedup by itself.

| Size | Reference wall ms | Candidate wall ms | Reference CPU ms | Candidate CPU ms |
|---|---:|---:|---:|---:|
| 1280x720 | 1.0203 | 0.1374 | 1.0051 | 0.1350 |
| 1920x1080 | 2.2844 | 0.3287 | 2.2609 | 0.3241 |
| 3840x2160 | 9.1187 | 1.2888 | 9.0329 | 1.2721 |

The proposed optimization is justified for a live comparison, not yet promoted
to default. Next: install APK manually, capture the same modes with reference
and fast paths, compare individual sync/pack stages and CPU, inspect frames,
and verify stream shutdown and reuse. No Magisk update or reboot is needed.
